FYREWAY INFRASTRUCTURE PLATFORM - OFFICIAL DOCUMENTATION
========================================================

PRODUCT OVERVIEW
================

Fyreway is a web-based platform for deploying and managing VPN infrastructure for mobile applications and SaaS products. The platform provides a landing page with product information and an infrastructure management interface.

Product Name: Fyreway
Platform Type: Web Application
Technology: React 18.3.1, TypeScript 5.8, Vite 5.4, Tailwind CSS

SYSTEM ARCHITECTURE
===================

The platform consists of three main components:

1. Landing Page (/)
   - Marketing and product information
   - Customer survey for infrastructure needs assessment
   - Pricing information
   - Feature descriptions

2. Infrastructure Management (/infrastructure)
   - VPN server configuration
   - Redis cluster configuration
   - Kafka cluster configuration
   - Multi-step deployment wizard

3. Detailed Logs (/detailed-logs)
   - System logs and deployment information

FREQUENTLY ASKED QUESTIONS
==========================

Question: How quickly can I deploy VPN servers?
Answer: Our platform provisions servers in under 10 seconds. Once you select your configuration and locations, your VPN infrastructure is ready to accept connections almost instantly.

Question: Which VPN protocols are supported?
Answer: We support WireGuard, OpenVPN, and IKEv2/IPSec out of the box. All protocols come pre-configured with optimized settings for mobile applications. WireGuard is recommended for best performance.

Question: Can I scale servers automatically?
Answer: Yes, our Growth and Enterprise plans include auto-scaling. The platform monitors your server load and automatically provisions additional capacity during traffic spikes, then scales down during quiet periods.

Question: Is there an SDK for mobile integration?
Answer: We provide native SDKs for iOS and Android that handle VPN connection management, server selection, and session handling. REST APIs are also available for custom integrations.

Question: What kind of uptime can I expect?
Answer: We guarantee 99.99% uptime SLA for all paid plans. Our infrastructure runs on enterprise-grade hardware with redundant networking and automated failover across multiple availability zones.

Question: How is bandwidth calculated?
Answer: Bandwidth is measured as the total data transferred through your VPN servers. Inbound and outbound traffic are both counted. Usage resets monthly, and you can monitor consumption in real-time via the dashboard.

Question: Can I bring my own server configuration?
Answer: Enterprise customers can customize server configurations, including kernel parameters, encryption settings, and networking rules. We work with your team to ensure optimal performance for your use case.

Question: What support is available?
Answer: Starter plans include email support. Growth plans get priority email with 4-hour response times. Enterprise customers receive 24/7 phone support and a dedicated account manager.

CUSTOMER SURVEY SYSTEM
======================

Purpose: The platform includes a comprehensive survey to assess customer infrastructure needs.

Access: Survey opens via "Explore the Platform" button on the hero section.

Survey Structure: 6 steps with multiple fields per step

Data Persistence: Survey data is automatically saved to browser localStorage and persists across sessions.

API Endpoint: POST /api/v1/customer-survey
Base URL: Configured via VITE_API_BASE_URL environment variable (default: http://192.168.18.68:4000)

SURVEY STEP 1: BUSINESS INFORMATION
====================================

Fields:
- Company or Startup Name (text, optional)
- Company Email (email, required, validated)
- Business Stage (select, optional): Idea Stage, MVP/Prototype, Live Product, Scaling
- Company Size (radio, optional): Solo Founder, 2-5 People, 6-20 People, 20+ People
- Primary Target Market (select, optional): Global, North America, Europe, Asia Pacific, Middle East, Latin America
- Type of VPN Business (select, optional): Consumer VPN App, Enterprise VPN, White-Label Solution, Reseller/MSP

Email Validation: Email field is required and must be valid format. Survey cannot proceed without valid email.

SURVEY STEP 2: APPLICATION DETAILS
===================================

Fields:
- Platform Type (checkboxes, optional): Android, iOS, Web, Desktop
- Estimated Monthly Active Users (select, optional): 0-1,000, 1,000-10,000, 10,000-50,000, 50,000-100,000, 100,000+
- Expected Growth in Next 6 Months (select, optional): 0%-25%, 25%-50%, 50%-100%, 100%-200%, 200%+
- Planned Launch Timeline (select, optional): Immediate, Within 30 days, Within 60 days, Within 90 days, Within 6 months
- Existing Product (checkbox, optional): "I have an existing VPN app/product"

SURVEY STEP 3: INFRASTRUCTURE REQUIREMENTS
===========================================

Fields:
- Initial Number of VPN Servers Required (select, optional): 1-3 servers, 3-5 servers, 5-10 servers, 10-20 servers, 20+ servers
- Preferred Server Regions (checkboxes, optional): US East, US West, EU West, EU Central, Asia East, Asia Southeast
- Expected Bandwidth per Server (select, optional): 100 Mbps, 500 Mbps, 1 Gbps, 5 Gbps, 10 Gbps
- Enable auto-scaling based on traffic (checkbox, optional)
- High Availability Requirement (radio, optional): Standard (99.9% uptime), Enterprise (99.99% uptime with multi-zone redundancy)

SURVEY STEP 4: SECURITY AND COMPLIANCE
=======================================

Fields:
- Preferred VPN Protocols (checkboxes, optional): WireGuard, OpenVPN, IKEv2, L2TP/IPSec
- Logging Policy (radio, optional): No Logs (Zero logging), Minimal Logs (Connection timestamps only), Custom (Define your own)
- Need custom security configurations (checkbox, optional)
- Compliance Requirements (checkboxes, optional): GDPR, HIPAA, SOC 2, None

SURVEY STEP 5: BILLING AND OPERATIONS

Fields:

- Need usage analytics dashboard (checkbox, optional)

- Level of Technical Support Required (select, optional): Community/Self-Service, Standard (Email Support), Priority (24h Response), Premium (Dedicated Support)

============================

Fields:

- Multi-region failover requirement (checkbox, optional)
- Custom integrations needed (checkbox, optional)
- Dedicated account manager needed (checkbox, optional)
- Additional Notes or Special Requirements (textarea, optional)

Submit Button: "Submit Request"

Survey Behavior:

- Users can close and resume survey later

INFRASTRUCTURE MANAGEMENT WIZARD
=================================

Access: Navigate to /infrastructure route

Purpose: Configure VPN servers, Redis clusters, and Kafka clusters

Structure: 3-step wizard with navigation controls

Steps:
1. VPN Server Configuration (Required)
2. Redis Cluster Configuration (Optional - can be skipped)
3. Kafka Cluster Configuration (Optional - can be skipped)

API Endpoint: POST /api/v1/customer-survey/infra
Base URL: Configured via VITE_API_BASE_URL environment variable

Navigation:
- Previous button: Goes back one step (disabled on step 1)
- Next button: Advances to next step (steps 1-2)
- Submit Configuration button: Submits entire configuration (step 3)

STEP 1: VPN SERVER CONFIGURATION
=================================

Required Fields:
- Deployment Mode (required): setup, deploy, update, rollback, maintenance
- Client/Organization (required): Text identifier for the organization

Deployment Mode Descriptions:
- setup: Initial configuration
- deploy: Deploy services
- update: Update configuration
- rollback: Revert changes
- maintenance: Maintenance mode

Server Configuration:
Minimum: 1 server required
Maximum: Unlimited servers

Per Server Fields:
- Environment (required): dev, stage, prod, qa
- Size (required): Select from available node sizes
- Region (required): Select from available regions

Add Server: Click "Add Server" button to add additional servers
Remove Server: Click X icon on server card (only if more than 1 server exists)

Available Node Sizes:
- s-1vcpu-1gb
- s-1vcpu-2gb
- s-2vcpu-2gb
- s-2vcpu-4gb
- s-4vcpu-8gb
- s-8vcpu-16gb

Available Regions:
Regions marked as "available" in the system. User selects from dropdown list.

Validation: Cannot proceed to step 2 without completing required VPN fields.

STEP 2: REDIS CLUSTER CONFIGURATION
====================================

Optional: This step can be skipped using the "Skip Redis" toggle switch

When Skipped: Displays message "Redis Configuration Skipped" with option to proceed

Required Fields (if not skipped):
- Cluster Name (required if configuring Redis)
- Cluster Type (required)
- Region (required)

Cluster Types:
- redis-single: Single Node (Dev)
- redis-prod-single: Production Single
- redis-sentinel-cluster-1: Sentinel Cluster
- redis-sentinel-prod: Sentinel Production

TLS Configuration:
- Enable TLS toggle (currently disabled/non-functional in UI)
- Status shows "Enabled" or "Disabled"

Node Configuration:
Three node role types with independent configuration:

1. Master Nodes
   - Purpose: Primary read/write nodes
   - Add/remove nodes with + Add master / X buttons
   - Per node: Size selection, Region selection
   - Minimum: 1 master node

2. Replica Nodes
   - Purpose: Read replicas for high availability
   - Add/remove nodes with + Add replica / X buttons
   - Per node: Size selection, Region selection
   - Can have 0 or more replicas

3. Sentinel Nodes
   - Purpose: Monitoring and automatic failover
   - Recommendation: Minimum 3 for quorum
   - Add/remove nodes with + Add sentinel / X buttons
   - Per node: Size selection, Region selection
   - Can have 0 or more sentinels

Each node displays: Role badge, node number, size dropdown, region dropdown, remove button

STEP 3: KAFKA CLUSTER CONFIGURATION
====================================

Optional: This step can be skipped using the "Skip Kafka" toggle switch

When Skipped: Displays message "Kafka Configuration Skipped" with option to submit

Required Fields (if not skipped):
- Cluster Name (required if configuring Kafka)
- Region (required)

Node Configuration:
Two types of Kafka nodes can be added:

1. Template Nodes
   - Click "Add Template Node" button
   - Pre-configured templates with standard settings
   - Select template from dropdown
   - Templates include: broker count, replication factor, partitions, retention hours

2. Custom Nodes
   - Click "Add Custom Node" button
   - Fully customizable configuration
   - Manual configuration of all parameters

Per Node Fields:
- Node Name (required): Text identifier
- Size (required): Select from node size dropdown
- Type badge: Shows "template" or "custom"

Template Node Configuration:
- Template dropdown: Select predefined template
- Displays: Broker count, Replication factor, Partitions, Retention hours (read-only preview)

Custom Node Configuration:
- Broker Count (number input)
- Replication Factor (number input)
- Partitions (number input)
- Retention Hours (number input)

Remove Node: Click X button on node card

Empty State: When no Kafka nodes configured, displays message "No Kafka nodes configured yet. Click Add Template Node or Add Custom Node to get started."

CONFIGURATION SUBMISSION
=========================

Submit Button: "Submit Configuration" on step 3

Submission Behavior:
- Collects VPN configuration (always included)
- Includes Redis configuration only if not skipped and cluster name is provided
- Includes Kafka configuration only if not skipped and cluster name is provided
- Sends POST request to /api/v1/customer-survey/infra
- Shows loading state: "Submitting..." with spinner icon

Success Response:
- Toast notification: "Infrastructure configuration submitted successfully!"
- Logs response data to console

Error Response:
- Toast notification with error message from API
- Default message: "Failed to submit infrastructure configuration"
- Does not clear form data on error

Payload Structure:
{
  "vpn": {
    "mode": "setup|deploy|update|rollback|maintenance",
    "client": "organization-name",
    "servers": [
      {
        "environment": "dev|stage|prod|qa",
        "size": "node-size-slug",
        "region": "region-slug"
      }
    ]
  },
  "redis": {
    "name": "cluster-name",
    "type": "cluster-type",
    "region": "region-slug",
    "enableTLS": true|false,
    "nodes": {
      "masters": [{"size": "size-slug", "region": "region-slug"}],
      "replicas": [{"size": "size-slug", "region": "region-slug"}],
      "sentinels": [{"size": "size-slug", "region": "region-slug"}]
    }
  },
  "kafka": {
    "name": "cluster-name",
    "region": "region-slug",
    "nodes": [
      {
        "name": "node-name",
        "type": "template|custom",
        "size": "size-slug",
        "template": "template-id",
        "config": {
          "brokerCount": 3,
          "replicationFactor": 2,
          "partitions": 10,
          "retentionHours": 168
        }
      }
    ]
  }
}
