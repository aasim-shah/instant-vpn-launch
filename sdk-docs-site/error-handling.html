Error Handling

Every SDK operation returns a VpnResult<T> — there are no unchecked exceptions. This makes error handling predictable and exhaustive.

The VpnResult Pattern

sealed class VpnResult<out T> {
    data class Success<T>(
        val data: T,
        val statusCode: Int = 200,
        val fromCache: Boolean = false
    ) : VpnResult<T>()

    data class Error(
        val exception: FyreWayException,
        val statusCode: Int? = null
    ) : VpnResult<Nothing>()
}

Convenience Methods

val result = sdk.getServers()

result.getOrNull()                // T?
result.getOrThrow()               // T (throws on error)
result.getOrDefault(fallback)     // T

result
    .onSuccess { data -> displayServers(data.servers) }
    .onError { exception -> showError(exception) }

Exception Hierarchy

The ErrorMessageMapper

when (val result = sdk.getServers()) {
    is VpnResult.Error -> {
        val message = ErrorMessageMapper.getMessage(result.exception)
        // "No internet connection. Please check your network."

        val title = ErrorMessageMapper.getTitle(result.exception)
        // "Connection Error"

        val action = ErrorMessageMapper.getSuggestedAction(result.exception)
        // "Check your internet connection and try again"

        val retryable = ErrorMessageMapper.isRetryable(result.exception)
    }
    is VpnResult.Success -> { /* ... */ }
}

Best Practices

✅ Do❌ Don't
Handle every VpnResult.ErrorIgnore errors silently
Use ErrorMessageMapper for user-facing textShow raw exception messages to users
Check isRetryable() before retryingRetry non-retryable errors endlessly
Use viewModelScope.launch for SDK callsUse runBlocking on the main thread
Re-authenticate on AuthenticationExceptionAssume tokens never expire
